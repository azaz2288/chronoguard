# Design and validity boundaries

Chronoguard separates two clocks that are often collapsed in notebooks. A sample's `decision_time` is when a prediction is made. A fact's `available_at` is when the production system could have read its value. For entity \(e\) and decision \(t\), the join selects the fact with the greatest availability time \(a \le t\). Facts published later are invisible even if they describe earlier events. Timestamps require explicit offsets and are normalized to UTC before comparison. Duplicate facts with the same entity and availability time are rejected because the winning value would be ambiguous.

For evaluation, each event has `start_at` and `end_at` for its label observation. A training event qualifies for a test block beginning at \(T\) only if its start is before \(T\) and `end_at + gap_hours <= T`. Earlier events that fail the second condition are purged. Test blocks are built from distinct start times, keeping events tied on a timestamp together. The train window expands with each fold; there is no random shuffling.

The generated plan lists every prior event as either training or purged and every event in the test block as test. `audit` recomputes these sets from the event CSV, checks unknown/duplicate/overlapping IDs, checks label horizons, and rejects omitted events. Its conclusion is limited by the accuracy of the supplied timestamps. It cannot prove that a feature pipeline did not fit preprocessing on all rows or that a delayed publication time was recorded honestly.

Outputs are deterministic for the same ordered inputs. Existing files require `--force`; temporary files in the destination directory and `os.replace` avoid partial output. This does not provide transactional consistency if source CSVs change during reading. Use immutable inputs for research records.

An optional maximum age further requires that the interval from fact availability to decision is no greater than the configured number of hours; the boundary is inclusive. The independent `audit-join` scans source facts directly rather than using the indexed join lookup. It is deliberately slower on large datasets, but reduces the chance that a selection bug passes both generation and audit.

The evaluation runner consumes an audited split plan and a numeric observation table keyed by the same sample IDs. Each fold computes imputation means, population standard deviations and ridge coefficients from its own training rows. Missing feature cells become the training mean (zero after scaling). The intercept is the training target mean and is not penalized. Fold and aggregate errors are calculated only from held-out predictions. Source fingerprints are recorded in the report. This protects against the runner itself fitting transforms on test rows; it cannot validate upstream feature construction, source timestamp honesty, or file immutability while reading.

The independent report audit reads the original events, plan and observation table again. It checks exact source fingerprints, plan validity and fold/test membership, then recomputes training statistics and validates the saved ridge coefficients by the normal equations. It recalculates predictions and all reported error metrics. This catches corrupted or mismatched artifacts without using the runner's fitting path. A valid report is still conditional on the authenticity of its inputs; SHA-256 is an identity check, not a signature or proof of honest data collection.

The version 2 report compares each held-out squared error with a training-mean baseline on the same event. Its paired loss delta is model loss minus baseline loss. When there are at least 10 held-out predictions, the seeded circular moving-block bootstrap resamples contiguous blocks of these paired deltas and reports percentile bounds. The predictions are concatenated in fold/test order. This is a descriptive uncertainty estimate conditional on the chosen block length and collected events, not a proof of significance or adjustment for tuning across many models. The report auditor independently recomputes predictions, losses, block draws and percentile bounds without importing the runner's bootstrap routine. Both paths use Python's seeded pseudorandom generator for reproducibility, so they are independent implementations of the same specified algorithm rather than statistically independent experiments.

`assemble` audits joined features against the original samples and facts before writing a numeric observation table. This creates a verifiable bridge from point-in-time features into the evaluation runner. Its target input is matched by sample ID and must be numeric and complete, but the command does not independently establish that event start/end timestamps are the correct decision and label-observation times. The caller must maintain that mapping. The end-to-end synthetic example exercises every stage, including both audits, and deliberately uses simple artificial values; its low error is not an empirical finding.

The join auditor groups source facts by entity but still directly scans each entity's candidates rather than sharing the join's sorted bisect path. This preserves algorithmic independence for fact selection while avoiding an unnecessary scan of other entities' facts for each sample. Its worst case remains quadratic when all samples belong to a single entity. Benchmark timings and methodology live in `benchmarks/README.md`.
